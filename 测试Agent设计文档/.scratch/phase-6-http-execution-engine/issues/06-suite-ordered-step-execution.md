# SUITE ordered step execution

## Parent

`../PRD.md`

## What to build

Support executing SUITE TestCases as ordered step flows. The executor should read structured steps generated by Phase 5, build and execute each step in order, preserve step-level request/response snapshots or structured step results, and stop dependent steps when a prerequisite step fails if configured.

This slice completes the flow-testing path without introducing UI automation or service direct invocation.

## Acceptance criteria

- [ ] SUITE TestCases execute ordered steps from structured TestCase step data.
- [ ] Each step can produce step-level request snapshot, response snapshot, status, duration, and assertion summary.
- [ ] Suite execution preserves the relationship between the suite case and participating ApiSpec/step references where available.
- [ ] A failed prerequisite step can stop dependent later steps when configured.
- [ ] Skipped dependent steps include clear reasons.
- [ ] The suite ExecutionRecord stores enough structured detail to diagnose which step failed.
- [ ] TaskCaseExecution links to the suite-level ExecutionRecord.
- [ ] Tests verify successful multi-step suite execution, failed prerequisite stop behavior, skipped dependent steps, and persisted step details.
- [ ] The slice does not implement browser/UI automation, service direct invocation, DB direct assertions, reports, frontend, or real LLM calls.
