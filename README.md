# ProbeFlow

ProbeFlow 是一个面向后端接口测试的智能测试系统。

它的核心不是“让大模型直接生成几条接口用例”，而是把真实业务流量、代码事实、接口文档、业务文档和历史经验融合起来，形成可审查、可修改、可执行、可沉淀的测试资产。

## 核心思路

ProbeFlow 以“业务流程”为中心生成测试。

系统可以先录制真实接口流量，再交给 AI（人工智能）分析，生成可视化流程文档或流程编辑界面。人工在这个界面里确认和修改流程、步骤、变量、断言、前置条件和异常分支。确认后的业务流程资产，才作为后续测试生成的主要依据。

```text
真实流量录制
-> AI 识别业务流程
-> 生成可编辑流程文档 / 界面
-> 人工确认和修正
-> 保存为业务流程资产
-> 生成链路测试、异常测试和回归测试
-> 执行测试并分析结果
-> 沉淀为长期经验
```

## 主要能力

- 从真实流量中还原用户实际业务路径。
- 从代码、OpenAPI（接口描述文件）、Swagger（接口描述文件）中识别接口。
- 从业务文档中提取业务规则、错误码、前置条件和测试要求。
- 生成单接口测试、链路测试和批量回归测试。
- 自动补充鉴权失败、参数缺失、非法值、边界值、业务前置条件失败等异常场景。
- 支持人工审核和修改 AI 生成的流程与测试草稿。
- 执行 HTTP 接口测试并生成结构化报告。
- 分析失败原因，区分环境问题、测试资产问题和真实系统问题。
- 将历史失败、人工修正和测试经验沉淀为长期记忆，反哺下一次生成和分析。

## 核心资产

- `SourceMaterial`：输入材料，例如代码、接口文档、业务文档、真实流量。
- `ApiSpec`：接口定义资产。
- `BusinessFlow`：人工确认后的业务流程资产。
- `TestCaseDraft`：待确认的测试草稿。
- `TestCase`：正式测试用例。
- `ExecutionRecord`：接口执行事实。
- `Observation`：执行结果分析。
- `MemoryItem`：系统沉淀的长期经验。
- `Report`：测试报告。

## 系统边界

当前阶段专注 HTTP 接口测试。

做：

- 接口分析
- 业务流程建模
- 用例生成
- 链路测试
- 回归测试
- 失败分析
- 测试报告

不做：

- 页面自动化
- 数据库直连断言
- 服务内部方法调用
- 直接用录制结果替代人工确认

真实流量录制只提供业务行为证据，不直接代表业务一定正确。快照对比只能证明“和上次一样”，不能证明“业务一定正确”。ProbeFlow 的关键是让 AI 先把真实流量整理成可读、可改、可确认的业务流程，再以这个流程为主生成测试。

## 一句话总结

ProbeFlow 想做的是：先录制真实业务行为，再由 AI 整理成可编辑的业务流程，最后基于人工确认后的流程资产生成、执行和持续改进接口测试。
